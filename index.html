01 — Instrument

Live component

The claim, running in front of you.

A studio that talks about instruments should show one. This plate is the working component from the Aperture case study: canvas-rendered, pause-aware, keyboard-operable, and static when motion is reduced.

Two parameters, one control surface. Drag anywhere inside the plate to tune frequency and aperture together, or use the sliders and the keyboard — which is how the component is actually operated in a lab.

  • Canvas, DPR capped at 2
  • Pauses off-screen and on tab hide
  • Static frame under reduced motion
  • Values exposed as text, not only pixels

02 — Position

Manifesto

The interface should feel like an instrument, not a form.

Most software asks people to think like the machine. We build the opposite: tools that behave like something you'd hold — an aperture you turn, a margin you write in, a signal you can read at a glance.

Qintara is a two-person practice by structure and a wide one by discipline: design research, interface craft and production engineering sit in the same room, on purpose.

We keep the stack small, the type large, and the state honest. If an interaction cannot be explained, it is not finished.

05 — Method

Three moves

We would rather be useful than impressive.

01

Read the situation

Watch the work happen, count the clicks that matter, write down the sentence the interface is failing to say.

02

Prototype in the medium

Motion and feel are decided in the browser, not in a static frame. We build the risky part first, in code, small.

03

Ship the instrument

Tokens, components and documentation travel with the build, so the team that inherits it can extend it without us.

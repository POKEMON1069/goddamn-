# 06 — Hugging Face investigation

Hugging Face **was reachable** (page fetches returned real content; the `/spaces`
directory and individual model cards loaded). This is what I looked at, and why the
answer is: *use nothing*.

## What was inspected

| Resource | What it is | Licence / access (as read) | Verdict |
| --- | --- | --- | --- |
| **Spaces directory** — <https://huggingface.co/spaces> | 1,507,989 running apps at time of inspection; categories include Image Generation, Background Removal, Image Upscaling, OCR, Data Visualisation, 3D Modeling | Mixed; each Space is independent | Useful as a *capability catalogue*, not as a dependency. Nothing there improves a static portfolio. |
| **`black-forest-labs/FLUX.1-schnell`** — <https://huggingface.co/black-forest-labs/FLUX.1-schnell> | 12 B-parameter text-to-image model, 1–4 steps | **Apache-2.0**, but the repo is **gated**: "You need to agree to share your information to access this model" — login required | Not used at runtime. Interesting option for offline image generation, but gated access + 12 B parameters is disproportionate for four abstract plates. |
| **`briaai/RMBG-1.4`** — <https://huggingface.co/briaai/RMBG-1.4> | Saliency/background-removal segmentation (IS-Net), 44.1 M params, ~245k downloads/month | **Non-commercial** ("source-available for non-commercial use"; commercial use requires a BRIA licence) | Rejected on licensing: a studio portfolio is commercial collateral. |
| Background-removal / upscaling Spaces | Browser demos wrapping segmentation and super-resolution models | Space-dependent; many run on ZeroGPU with queueing | Rejected: no need. The plates are already composed at the right size and the design does not cut subjects out. |

## Evaluation against the actual project need

| Criterion | Assessment |
| --- | --- |
| **Clear benefit** | None. The site's claims are about interface craft, not AI capability. Adding a model would introduce a feature the audience did not ask for, and would compete with the real proof (the canvas instrument). |
| **Latency** | Any hosted inference adds 0.5–30 s per call; ZeroGPU Spaces queue. The site currently has no network dependency at all after first load. |
| **Hosting** | A Space cannot be embedded reliably (iframe + CORS + cold starts) and would couple a static site's availability to a third party. |
| **Privacy** | A visitor's input would leave the origin — requiring consent copy and a privacy note for a portfolio that otherwise stores nothing. |
| **Cost** | Free tiers are rate-limited/sleep after inactivity; production inference is paid. No budget was authorised. |
| **Licensing** | The two most relevant models are either gated (FLUX) or non-commercial (RMBG). |

## Decision

**No Hugging Face resource is used, bundled, or called at runtime.** The recommendation
is to proceed without one, and the site reflects that: zero third-party requests, no AI
feature, no API keys anywhere in the client bundle.

## Note on the imagery (for transparency)

The four photographic plates were produced with the image-generation tool available in
this environment, art-directed to a single palette (bone paper, graphite, burnt
vermilion, a trace of ultramarine) and then compressed to WebP at two widths. They were
**not** generated by calling a Hugging Face model, and no HF token or credential exists in
this repository.

If a future version needed generative imagery *at build time*, `FLUX.1-schnell`
(Apache-2.0, gated) would be the defensible choice — run offline, commit the outputs, and
keep the site itself free of inference. Background removal is not needed, and `RMBG-1.4`
would have to be replaced with a commercially licensed model if it ever were.

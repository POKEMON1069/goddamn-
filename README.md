# Qintara — a demonstration studio portfolio

A multi-page portfolio for **Qintara**, an invented interface studio, built around a
single idea: *an interface should feel like an instrument, not a form*. The site is a
static, dependency-free front end generated by Vite, with one live canvas component,
an editorial design system, and case studies written the way a real studio would
document them — context, constraint, decision, trade-off — without inventing
testimonials, awards or metrics.

> **This is a demonstration build.** "Qintara" is a fictional studio identity created
> for this exercise. The four case studies are written examples, not client work. The
> contact address uses the reserved `.example` domain and is not a live inbox.

---

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # static output in dist/
npm run preview    # serve the production build
```

Node 18+ (developed on Node 22).

### Checks

```bash
npm test              # build + accessibility/structure audit + behavioural tests
npm run test:a11y     # axe-core in jsdom + link, heading, contrast and CSS checks
npm run test:behaviour # menu, form, copy button, fallbacks (8 assertions)
npm run test:visual    # optional screenshots; needs a working Chromium (see below)
```

`npm test` writes `audit-report.json`. See [docs/10-verification.md](docs/10-verification.md)
for the results and for the honest list of what could **not** be verified in the build
environment.

## Stack

| Decision | Choice | Why |
| --- | --- | --- |
| Build | **Vite 5** | Static multi-page output, instant dev server, hashed assets. No runtime framework. |
| Language | **Vanilla ES modules + hand-written CSS** | A portfolio of this size gains nothing from React; ships ~5 KB gzipped JS. |
| Templating | **~40-line Vite plugin** (`@include` partials + `{{token}}` content) | Shared header/menu/footer and one content file, without a template engine dependency. |
| Type | **Fraunces** (variable) + **IBM Plex Sans/Mono**, self-hosted | Editorial display voice + technical text voice. Both SIL OFL 1.1. |
| Motion | **CSS transitions + one `requestAnimationFrame` loop** | No animation library needed; reduced-motion treated as a design state. |
| Images | Four art-directed plates, AVIF-free WebP at two widths | 8–190 KB each; smaller than any animation or video alternative. |

Zero runtime dependencies. No analytics, cookies, trackers or third-party requests at
runtime (`grep` the built HTML: the only external URL is the GitHub profile link).

## Editing the site

**Change contact details, domain or repo URL** — edit `content/site.json` only. Every
page, partial and meta tag reads `{{email}}`, `{{domain}}`, `{{url}}`, `{{repo}}`,
`{{year}}` at build time; an unknown token fails the build loudly.

**Change navigation or footer** — edit `partials/`. All pages include them.

**Change colours, type or spacing** — edit `src/styles/tokens.css`. Components consume
tokens only; there are no hard-coded colours outside that file except the canvas palette
in `src/js/instrument.js`, which is documented there.

**Add a case study** — copy a sibling folder under `work/`, update its `<head>` metadata
and copy, add the link to `partials/site-menu.html`, `partials/site-footer.html`,
`work/index.html`, the home work rows, and the `rollupOptions.input` list in
`vite.config.js`.

**Replace the plates** — drop new images into `src/assets/plates/` at 1264×848 and
760×510 (3:2), update the `src`/`width`/`height` attributes. Keep the intrinsic sizes:
they are what prevent layout shift.

## Deployment

`npm run build` emits a fully static `dist/`. Any static host works (Netlify, Cloudflare
Pages, GitHub Pages, S3+CDN). Then:

1. Set `url` in `content/site.json` to the production origin and rebuild so canonical
   and Open Graph URLs are absolute.
2. Serve `404.html` for missing paths (most hosts do this automatically; Netlify needs
   nothing, GitHub Pages needs a `CNAME` or a 404 fallback).
3. Cache hashed assets in `/assets/*` for a year; keep HTML short-lived.

Full notes: [docs/09-architecture.md](docs/09-architecture.md).

## Known limitations

- **No pixel-level visual verification in the build environment.** Chromium in this
  sandbox cannot start (missing NSS/NSPR libraries, no package manager access, no
  alternate browser). Layout was verified through the CSS contract, structural DOM
  checks and accessibility tooling — not screenshots. Run `npm run test:visual` on a
  machine with a working browser before shipping.
- The contact form composes a `mailto:` draft; it does not send mail. A static site
  needs a form endpoint (or a mail provider) for that, which was deliberately out of
  scope.
- Copy is written for a fictional studio. Replace the case studies, facts and dates
  before using the site for a real practice.
- The canvas instrument is a demonstration of interaction craft, not a production
  measurement tool.

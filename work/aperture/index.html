Case 01 — Interface system

Aperture

A calibration interface for an optical metrology team. The brief was not "build a dashboard" — it was "let an operator feel where the lens is" before reading a number.

01

Context

Two operators at a bench, aligning lens assemblies against a reference. The existing tool was a numeric readout paired with a spreadsheet export: technically complete, perceptually empty. To know whether a mount was seated, an operator had to read three fields, remember the tolerance, and compare — in a room kept deliberately dim.

The team had already diagnosed the symptom themselves: new operators re-checked the same value four or five times, not because the number changed, but because nothing in the interface confirmed their action had landed.

Constraints

Gloves. Low light. Keyboard required. No new hardware.

02

Constraint

The real limits

  • Input. Operators wore nitrile gloves; sliders with 2px thumbs were unusable in practice.
  • Light. The bench room was dim to protect samples, so a bright UI raised glare rather than reducing it.
  • Time. A calibration cycle could not grow; any interaction added had to replace an existing one.
  • Proof. The team could not change the measurement hardware, so the interface had to carry the improvement alone.
03

Decisions

Three choices shaped the build. Each one has a cost, and the cost is written next to it — a portfolio that only shows the upside is a brochure, not a case study.

Instrument, not dashboard.

A single circular control replaced six stacked sliders, mapping directly to the physical aperture. Trade-off: you cannot compare six values at once; you get one precise gesture instead.

One parameter in focus.

Frequency and aperture are edited one at a time, with the other held in a persistent readout. Trade-off: slower for experts until shortcuts are learned, so keyboard stepping was designed at the same time as the pointer interaction.

Ink on paper, not control-room black.

Warm paper with a single vermilion state colour, inverted only inside the measurement plate. Trade-off: less "technical" in a screenshot; measurably less glare on a dim bench.

04

Craft

The component below is the actual build, not a render. It runs on canvas at device pixel ratio capped at 2, pauses when it leaves the viewport, and draws a single static frame when the visitor prefers reduced motion. Every value is also reachable from the sliders and the keyboard, so the plate is a demonstration rather than a gate.

Accessibility and performance notes

  • Pointer targets are 44 × 44 CSS pixels minimum, sized for gloved hands.
  • Range inputs are native, labelled, keyboard-steppable, and expose aria-valuetext.
  • The canvas is decorative; every value it displays is available as text.
  • One animation frame loop, cancelled off-screen and on tab hide.

05 — Signals

What we would measure, instead of inventing a number.

Because this brief is written rather than delivered, we claim no results. These are the signals the work would be judged by — chosen because they can be observed at the bench, not because they look good in a deck.

  • S1

    Repeat checks per calibration

    The original symptom, measured directly: does the operator still re-read the same field?

  • S2

    Time to first correct seating

    Observed on a new operator's first three cycles, not averaged across the team.

  • S3

    Errors on the three routine adjustments

    Counted per shift, because a beautiful interface that adds errors has failed.

  • S4

    The words operators use

    If they start saying "seat it" instead of "set the third field", the metaphor transferred.
